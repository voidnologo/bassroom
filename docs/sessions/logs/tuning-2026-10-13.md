## Steps

### Step 1 — hardware and gain

**Finding 1 (confirmed live): the input device list is empty until the engine is already running.**

The Setup dropdown offered only the hardcoded `"Default input"` option
(`Setup.tsx:54`). Real devices come from `devices`, populated by
`refreshDevices()`, which runs only once `state === 'running'`
(`Setup.tsx:26`) or at the end of `start()` (`AudioProvider.tsx:89`). Chrome
also withholds device labels until permission is granted, and the only
`requestPermission()` call is inside `start()`.

So the first start of any session runs on the system default. On this Mac the
default is the MacBook Pro microphone, not the Scarlett — `system_profiler
SPAudioDataType` listed both, so the hardware was never the problem.

Confirmed by Caleb: pressing "Start listening" and allowing the prompt
populated the list immediately.

Consequence: a user following the README ("go to Setup, start the input")
records their laptop microphone until they notice. It produces plausible data
from the wrong source, which is worse than failing outright.

Proposed fix, deferred until after the battery so it does not delay the
measurements: call `requestPermission()` and `refreshDevices()` when the Setup
screen mounts, so the list is populated before the first start. Selecting a
device while running must also either restart the stream or say that it will
not take effect until the next start.
